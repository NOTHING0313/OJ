# 题库难度分级：设计与验收

## 变更前设计
风险 R4（新增持久化列），范围为用户明确要求的题库难度。只新增元数据，不改判题、评分、赛季或挑战难度。

- Domain 新增 ProblemDifficulty：0 未分级、1 简单、2 中等、3 困难。Problem 是唯一权威来源；现有题目迁移为 0。
- Application 的创建/更新及详情/列表携带 difficulty。Update 可空：省略保留现值，显式 0 清除；服务与 API 验证非法枚举。
- Infrastructure 复用既有元数据权限、AuthoringVersion 和审计；只改难度不生成判题版本。新增整型列及 0..3 检查约束，无数据删除。
- Frontend 编辑表单设置难度，出题草稿包含难度；旧草稿缺少该字段按未分级兼容。题目列表只对分级标题上色，未分级不增加颜色规则；工具提示/无障碍名称提供文字难度。
- 不复用 ChallengeTaskDifficulty，因为它描述挑战棋子等级且有 6 级，与本需求不同。

## 验证计划
服务测试覆盖创建、更新、省略、清除、非法值、权限、版本与判题版本不变；迁移检查与本地应用；前端类型/构建、草稿兼容测试、真实组件难度保存与颜色检查。只在测试环境验证，不修改已有题目分级。

## 状态
已完成并在本地验证。已有题目保持未分级，未自动修改实际题目难度。

## 实现与兼容
- 新建/编辑题目提供四档选择，保存、重新打开、草稿恢复与清除分级均已覆盖。题库标题简单为绿 `#4ade80`、中等为黄 `#facc15`、困难为红 `#f87171`。
- 视觉检查发现主题的强制强调色覆盖难度色；将该主题规则限定为未分级标题后，默认与 Root 主题均验证颜色正确，未分级仍沿用原主题。
- 修改集中于 Problem 实体/枚举、请求与响应 DTO、ProblemService、EF 配置/迁移，以及 problemsApi、题目编辑/列表、草稿工具和样式。相关测试见 ProblemMetadataUxTests、草稿单测与 frontend/tests/reliability.tsx、difficulty.tsx。
- 本地已应用 `20260905125143_AddProblemDifficulty`；其他部署环境须在更新 API 前应用迁移。迁移只增加默认 0 的列与范围约束，不删除现有数据。
